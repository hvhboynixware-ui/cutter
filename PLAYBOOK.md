# Playbook: Cutter — приложение для нарезки видео в шортсы

GOAL: пользователь открывает окно, кидает видео или ссылку YouTube, через N минут получает
готовые вертикальные клипы с субтитрами и может загрузить их на площадку по кнопке.

STEPS:
1. Каркас: локальный сервер + окно, настройки, очередь задач.
2. Пайплайн нарезки: ffmpeg → faster-whisper → LLM → рендер + субтитры.
3. LLM-провайдеры с фолбэком; скачивание YouTube через yt-dlp.
4. Интерфейс: 4 экрана, состояния пусто/загрузка/ошибка, адаптив до 375px.
5. Загрузка на площадки: Playwright + Dolphin/AdsPower, режим тренировки.
6. Документация, тесты, репозиторий.

DONE MEANS:
☑ пайплайн выдаёт клипы 1080×1920 с прожитыми субтитрами (проверено e2e по HTTP, файлы отдаются)
☑ прогресс и отмена работают, ошибки показываются человеческим текстом
☑ UI проверен скриншотами 1440px и 375px, глазами просмотрены оба
☑ консоль без ошибок, 404 нет
☑ пусто / загрузка / ошибка отработаны на всех экранах
☑ worst-case: длинный заголовок клипа, 60-символьный ник, пустой список клипов
☑ все суммы/счётчики считаются (число клипов, длительности, прогресс)
☑ тексты реальные, на русском, без lorem ipsum
☑ 84 офлайн-теста зелёные
☑ защита от обхода путей на отдаче медиа
☑ репозиторий: README, LICENSE, .gitignore, CI
☑ окно приложения запускается: Cutter.exe (C# WebView2) поднимает cutter_backend.exe и ждёт health
☑ эффекты кадра, музыка с дакингом, защита от повторов, метрики — проверено рендером (1080×1920, звук есть)
☑ MSI собирается и ставится per-user без админа (51 PASS), удаляется чисто
☑ 100 офлайн-теста, включая пак музыки и эффекты
☐ загрузка на живых аккаунтах (нужны аккаунты пользователя — делается в режиме тренировки)
☐ пуш на GitHub (ждёт `gh auth login` от пользователя)

TOOLBOX:
- `app/core/pipeline.py` — единственное место, где режется видео
- `app/core/upload/selectors.py` — единственное место, где живут селекторы площадок
- `app/web/assets/app.css` — токены и весь визуал
- `tools/e2e_check.py` — дымовой тест по HTTP
- `tools/fetch_fonts.py` — локализация шрифтов

RETRO (после первой сборки):
- CUDA в ctranslate2 определяется как «есть GPU», но без cublas падает/висит → по умолчанию CPU, GPU по флагу.
- HF-модели из РФ недоступны → источник ModelScope, `get_model` в приложении.
- Генерация id задачи отдельно от каталога ломала ссылки на медиа → id задачи задаётся снаружи.
- Один и тот же `state.clips` в UI был и числом, и списком → разнесено на `clipCount` / `clipList`.
